# 本地 MCP 服务自检清单（stdio）

写或改一个本地 MCP 服务（例如本地技能库、数据索引或工具桥接服务）时启用。要从零做一个对接外部 API 的大服务，先用官方的 mcp-builder 技能，再回来过这份清单。

## 1. 协议与传输
- stdout 只写协议消息：一行一条 JSON，消息内不带换行。日志全部写 stderr。
- 只声明自己真的实现了的能力。
- stdin 关闭或读到 EOF 时尽快退出。
- 收到无法解析的输入回 JSON-RPC 解析错误（-32700）；未知方法回 -32601；参数不对回 -32602。不要静默丢弃。
- 工具本身执行失败时，用正常结果加 `isError: true` 返回，让模型看得到原因；协议层的错误才用 error 对象。
- 版本：规范在 2026-07-28 这一版取消了 initialize 握手，改为每个请求在 `_meta` 里带协议版本，并要求服务实现 `server/discover`；更早的版本靠 initialize 握手。一个服务可以两种都支持。动手前到 modelcontextprotocol.io 看当前规范，并确认要接的每个客户端用的是哪一代。

## 2. 身份与权限
- 调用方是谁由服务端决定（启动配置或环境变量），不采信工具参数里自报的名字。请求元数据里客户端自带的身份同样只是自述。
- 身份缺失或不认识时，拒绝启动或拒绝请求，不要默认放行。
- 工具分成只读和会写入两类，并在工具注解里标明（只读的标 readOnlyHint）。
- 会改共享状态的操作只开放“提交提案”，由人在界面上看过差异后批准；不提供“声称已获授权就直接写”的工具。
- 一个调用方不能改到别的调用方的配置或目录。

## 3. 输入与文件
- 每个参数都校验类型、长度和取值范围；ID 只允许白名单字符。
- 路径参数限制在声明过的根目录内，解析符号链接后再检查一次；目录遍历要有深度和文件数上限。
- 更新记录时与已有数据合并，没传的字段保持原值。
- 写文件用“临时文件、落盘、重命名”三步；多个进程会同时写的文件要加跨进程锁，拿到锁之后再读。

## 4. 输出与外部请求
- 列表类工具默认返回精简字段，详情留给单独的工具；单次返回控制在几 KB 以内。
- 返回内容里不带密钥、令牌或本机的隐私路径。
- 对外请求设超时并检查状态码；联系邮箱之类的标识从配置读，不写编出来的地址。

## 5. 测试与发布
- 用真实入口做冒烟测试：启动进程，经 stdin 发请求，断言 stdout 的每一行都是合法 JSON。
- 测试要覆盖：未知身份、坏 JSON、越界路径、并发写入、超大输入。
- package.json、服务自报的版本和文档里的版本号保持一致。
- README 写明启动命令、需要的环境变量、数据存在哪里。
