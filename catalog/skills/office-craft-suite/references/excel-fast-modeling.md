# Excel 专业建模蓝图（FAST + ICAEW + 华尔街规范 + Excel 365）

本蓝图用于财务、量化分析、预算、进度跟踪与结构化决策模型（`.xlsx`）。参考公开行业标准 **FAST Standard**（Flexible, Appropriate, Structured, Transparent）与 **ICAEW Twenty Principles for Good Spreadsheet Practice**。

---

## 1. 工作簿结构与单向数据流（Tab Architecture）

按从左到右、从上到下的单向流组织工作表，**杜绝无说明的循环引用**：

| 序号 | 建议标签名 | 职责边界 | 规则 |
| :--- | :--- | :--- | :--- |
| 1 | `00_Cover_Control` | 目录、版本号、作者、假设开关与全局错误总警报 | 顶部放置总自检格：`=IF(COUNTIF('99_Checks'!C:C,"<>0")>0,"CHECK FAILED","OK")` |
| 2 | `01_Inputs` | 唯一输入与假设源（税率、汇率、折现率、单价、基准日期） | 每个假设标明**单位**与**来源说明**；后续所有计算表只引用这里 |
| 3 | `02_Calc_Engine` | 模块化分步计算区（收入、成本、折旧、现金流、敏感性） | 同一行的公式在时间轴各列完全一致，可横向拖拽复制 |
| 4 | `03_Outputs_Summary` | 面向读者的管理摘要、关键指标卡（KPI）与原生图表 | **只做引用与汇总，不藏复杂中间计算** |
| 5 | `99_Checks` | 资产负债配平检验、总和交叉核对、空值/除零检查 | 正常为 `0`（或 `TRUE`），异常标红并汇总至封面总警报 |

## 2. 华尔街通用视觉与字体色码（Wall Street Color Coding）

让任何审阅者扫一眼就能区分「手填假设」和「公式结果」，严禁五颜六色装饰底纹：

- **蓝色文字（`#0000FF`）**：硬编码输入项 / 原始假设值（可配极浅底色 `#FFF2CC` 或 `#EBF1DE` 标示可编辑区）。
- **黑色文字（`#000000`）**：同工作表内部公式。
- **绿色文字（`#008000`）**：跨工作表引用链接（如 `='01_Inputs'!$C$8`）。
- **红色文字（`#C00000`）**：外部工作簿链接、异常警报或需人工复核的临时占位。
- **表头与合计行**：深岩灰/深藏青底白字（`#1F3A5F`）配清晰细横线，合计行加顶部单细线 + 底部双底线（Accounting double underline），禁用花哨粗黑竖网格。

## 3. FAST 公式卫生铁律

1. **严禁在公式中藏“魔法数字”**：
   - 错误：`=B12 * 0.2`
   - 正确：将 `20.0%` 写入 `01_Inputs` 并命名单元格或显式引用 `=B12 * '01_Inputs'!$C$6`。
2. **拆解复杂嵌套**：避免超过 2 层的 `IF` 嵌套或超过一行的怪兽公式；把中间逻辑拆为清晰辅助行，使审阅者能按 `F2` 一步看懂。
3. **统一格式与单位**：
   - 金额：`#,##0;(#,##0);"-"`（负数括号显示，零值横杠显示）
   - 比率：`0.0%`；倍数：`0.0"x"`；日期：`YYYY-MM-DD`
   - 列宽预留余量（至少比最长字符宽 4 字符），彻底杜绝 `###` 截断；冻结首行与左侧标签列。

## 4. Excel 365 动态数组工具箱与跨工具兼容分界（关键！）

先确认交付对象是在**本机桌面 Excel 365** 打开，还是需要兼容 **LibreOffice / 旧版 Excel / Python 自动重算**：

| 场景 | 推荐函数集 | 工程注意 |
| :--- | :--- | :--- |
| **桌面 Excel 365 交互建模**（推荐） | `XLOOKUP`、`FILTER`、`UNIQUE`、`SORT`、`LET`（消除重复子表达式）、`VSTACK` / `HSTACK`、`GROUPBY` / `PIVOTBY`、`SUMIFS` | 可大幅减少冗余辅助表；但避免炫技式超长 `LAMBDA`/`REDUCE` 嵌套，可读性优先于“一格写完” |
| **跨平台兼容 / 自动校验交付** | `SUMIFS`、`COUNTIFS`、`AVERAGEIFS`、`INDEX / MATCH`、`SUMPRODUCT`、`IFERROR` | **稳妥底线**：在任何版本 Excel、LibreOffice Calc 与预览器中都不会报 `#NAME?` |

### `openpyxl` / 脚本生成 `.xlsx` 的 4 个致命工程坑（必查）
1. **无缓存公式值**：`openpyxl` 写出的公式单元**不含计算缓存**；用 `openpyxl.load_workbook(..., data_only=True)` 读未重算文件会拿到 `None`，且**绝不可用 `data_only=True` 打开后再保存**，否则全表公式会被永久抹成死值。
2. **动态数组 `_xlfn.` 前缀陷阱**：通过 `openpyxl` 写入 `XLOOKUP`、`FILTER`、`UNIQUE`、`LET`、`GROUPBY` 时，若未写内部前缀（如 `_xlfn.XLOOKUP`、`_xlfn._xlws.FILTER`）及动态数组元数据，打开时容易出现 `#NAME?` 或 `@` 隐式交集符号。Python 批量建表若不经过桌面 Excel 365 校验，优先使用 `INDEX/MATCH` + `SUMIFS`。
3. **带空格表名必须加单引号**：写成 `'Cash Flow'!B5`，漏单引号会导致 Excel 弹窗修复工作簿。
4. **交付前零错误复核**：交付前须用脚本或本机 Excel 检查全表是否存在 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`；若本机无法自动触发 Excel 重算，须在交付说明中明确告知用户“首次打开 Excel 后按 `Ctrl+Alt+F9` 确认公式刷新”。
